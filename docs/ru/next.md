# Что дальше строим — очередь

Состояние на 2026-10-25. Полный цикл доставки реализован и врезан —
система работает как задумано на одном инстансе. Порядок — по
зависимостям, не по важности.

## Блокирует сейчас

1. **Docker Desktop** — единственный блокер живого прогона (P-12):
   compose → MockReceiver → LoadGen → дашборд + /metrics. Чеклист —
   в `docs/tasks.md` под P-12.
2. **Ревью юзера** — защита делегированного TASK-005 (S2–S5),
   семантика DLQ/replay, вопросы L1/L3/L4, В7. Всё в
   `docs/guides/open_questions.md` с указателями на код.

## Следующая волна

3. **TASK-007 · Хаос-сценарии** — в паре: юзер придумывает ≥5 сбоев,
   тесты вместе. Полигон готов: MockReceiver `?mode=flap|500|429|slow|drop`.
4. **TASK-009 · Метрики** — экспозиция готова (`/metrics` + панель в
   дашборде); осталось решение юзера по таблице «метрика → сбой».

   если юзер решит чинить, а не документировать.

## Scale-волна (когда будет нужен второй инстанс)

7. **Redis rate limiter** — in-memory ломается при 2+ инстансах (D6/L1).
8. **Leader-election sweeper'а** — два sweeper'а будут драться за due;
   клейм через PG/Redis.
9. **`db.Database.Migrate()` на старте** — два инстанса могут гонять
   миграцию одновременно (EF Migrate не concurrency-safe). Варианты:
   миграция как отдельный job/step в CI, или advisory lock в PG.
10. **ConsistentHashRing врезка** — готов и оттестирован, ждёт повода.
11. ~~`/stats` seq scan~~ ✓ закрыто `StatsCache` (2026-10-26): один
    снапшот на /stats+/metrics, TTL 3с — seq-scan максимум раз в 3с.
